# A股短线竞价选股系统 v7.1 实施 spec(implementation contract)

> 本文档是 v7.1 的实施合同。所有字段名、阈值、模块拆分均以本文档为准。
> v7.0 baseline doc 已废弃,v7.1 后续修改通过 PR 改本文档,不再口头讨论。

## 0. 设计原则

1. **数据时点严格隔离**:盘前(09:25)只用当日竞价数据 + T-1 capture;盘中(10:01)只用当日盘中数据 + 盘前产出 + T-1 capture。
2. **主线口径统一**:`home.kaipan.plate.summary` 为唯一主线源;`review.fupan.plate` 不再用于主线判断。
3. **沉睡数据激活**:`review.ltgd.range`、`home.ztpool`、`cashflow` 特大单、`dailyline`、`home.qxlive.top_metrics` 历史序列。
4. **标签正交化**:每个标签解决一个独立维度,组合成互斥的 setup。
5. **可回测**:所有阈值都在 yaml 头部参数化;backfill 脚本必须先于上线就绪。

## 1. 已锁定的 3 个设计决策(默认值,可在 backfill 后微调)

| # | 决策点 | 锁定值 | 理由 |
|---|---|---|---|
| 1 | `time_score` 衰减公式 | `max(1 - minutes/240, 0)`(以 09:25=0,4 小时线性衰减,午休 90 分钟跳过) | 11:00 前封板 ≥ 0.6;午后封板还有 0.3-0.5;13:00 后才接近 0,不再苛刻惩罚午后封板 |
| 2 | `review.ltgd.range` 周期 | 固定使用 5 日窗口(`周期 == "5日"`) | 短线龙头身份验证只看 5 日累计涨幅,10/20/50 日窗口在 v7.1 不复用,仅 v6 兼容路径保留 |
| 3 | `ice_dragon` 优先级机制 | 拆成 `setup A_ice`(priority 3.5) vs `setup A`(priority 3.0),不动 sort key | 让排序天然处理优先级,避免引入 ad-hoc 提升逻辑 |

## 2. 实际字段名清单(以 capture 为准,所有 v7.0 占位字段名已修正)

### 2.1 `home.kaipan.plate.summary`(主线源)

主标签层字段:
- `主标签序号`(int)
- `主标签名称`(str)
- `主标签代码`(str)
- `板块强度`(str,显示文本)
- `板块强度原值`(int/float,数值排序用)
- `主力流入`(str,显示文本)
- `主力流入原值`(float,**万元**)
- `主力流入真实金额`(float,**元**)
- `涨停数量`(int)
- `子标签数量`(int)

子标签层(在落盘 JSON 的 `meta` 中):
- `meta.subplates`(全集) 或 `meta.top_plates[*].subplates`
- 每条字段:`{子题材序号, 子题材名称, 子题材代码, top_plate_name, top_plate_code}`

百分位计算:
- 取 top 20 主标签,对 `板块强度原值` 和 `主力流入原值` 分别降序,得到 `rank_strength`、`rank_inflow`(均 1-20)
- `pct_strength = (21 - rank_strength) / 20`(rank=1 → 1.0,rank=20 → 0.05)
- `pct_inflow` 同公式

### 2.2 `auction.jjlive.fengdan`(注意是 jjlive,不是 jjyd)

字段:
- `9:15`、`9:20`、`9:25`(均为字符串,可能含 "亿"/"万"/"-")
- 必须先用 `parse_money_to_wan` 转 float 万,再做任何数值运算

fengdan 缩减率公式:
```
amt_925 = parse_money_to_wan(row["9:25"])
amt_920 = parse_money_to_wan(row["9:20"])
if amt_920 is None or amt_920 < params.fengdan_amount_920_floor_wan:
    fengdan_reduction = None  # setup E 视 None 为通过
else:
    fengdan_reduction = (amt_925 - amt_920) / amt_920
```

### 2.3 `review.fupan.plate`(涨停品质)

核心字符串字段(必须解析):
- `封单额`、`成交额`("3.82亿" / "6070万" / "-")
- `开板`(实测都是数字文本如 "0"/"11"/"2",但仍走 `parse_int_safely` 防御)
- `首次封板`、`最后封板`(格式 "HH:MM:SS")

zt_quality 复合分公式(三因子加权,锁定 v7.1 默认):
```
open_punish = min(parse_int_safely(开板) / 3, 1.0)             # 开板次数惩罚
seal_amt   = parse_money_to_wan(封单额)                         # 万
trade_amt  = parse_money_to_wan(成交额)                         # 万
seal_solid = min(seal_amt / max(trade_amt * 0.3, 1.0), 1.0)    # 封单 / (成交 * 30%)
minutes    = parse_time_to_minutes_after_open(最后封板)
time_score = max(1 - minutes / 240, 0)                          # 4 小时线性衰减
score      = (1 - open_punish) * 0.4 + seal_solid * 0.4 + time_score * 0.2

score >= 0.7 → clean ; 0.4 <= score < 0.7 → average ; score < 0.4 → dirty
```

任一因子的 parse 结果为 None → 该因子分置 0,且整条记录 zt_quality 不晋升 clean。

### 2.4 `cashflow.stock.today`(资金流)

确认存在的字段(已通过 2026-04-24 capture 核实):
- `排名`(int)
- `主力净流入`(float,万)
- `特大单净流入`(float,万)
- `大单净流入`、`中单净流入`、`小单净流入`(float,万)

super_ratio 公式:
```
if 主力净流入 is None or 主力净流入 < params.super_ratio_main_inflow_floor_wan:
    super_ratio = 0.0  # 主力流入接近 0 或负,super_ratio 没有意义
else:
    super_ratio = 特大单净流入 / 主力净流入
```

### 2.5 `home.ztpool`(封板验证)

字段:
- `分组名称`:实测有 `首板`、`1进2`、`2进3`、`3进4`、`5进6`(可能不连续,以当日 capture 为准,**不要硬编码组名**)
- `状态`:`成` / `炸` / 其他
- `状态样式`:CSS class(`success` / `zha` / `fail`)— 解析时优先用此字段
- `晋级数`(int)、`样本数`(int)、`晋级率文本`(str,如 "12%")

首板晋级率(用于 regime 降级判定):
```
for row in ztpool:
    if row["分组名称"] == "首板":
        promo_rate = row["晋级数"] / row["样本数"] if row["样本数"] > 0 else 0.0
        break
```
绝不解析 `晋级率文本` 的 "12%" 字符串做数值运算。

zt_seal_verified:
```
for row in ztpool:
    if row["代码"] == candidate_code:
        return parse_status_to_seal_verified(row["状态"], row["状态样式"])
return "none"
```

### 2.6 `home.qxlive.top_metrics`(情绪)

问题:同一天有多个 `time_point`(09:26、10:02、10:09 等)。

回溯历史 T-1 / T-2 时严格规则:
```
1. 先取 time_point <= "09:30" 的最早一份
2. 若整天没有 09:30 之前的快照,取整天最早一份(并打 warning)
3. 不得使用 10:00 之后的快照(避免回溯混入盘中数据)
```

### 2.7 `dailyline/stocks/<code>.csv`(技术面)

- 文件名:6 位代码,如 `000001.csv`(纯 6 位)
- 内部 `code` 列:带 `sz.` / `sh.` 前缀,如 `sz.000001`(用 `normalize_dailyline_code` 提取 6 位)
- 列:`date,code,open,high,low,close,preclose,volume,amount,adjustflag,turn,tradestatus,pctChg,isST`

tech_profile 计算:
```
如果文件不存在 OR 最新行的 date != T-1 → tech_profile = "unknown"
指标:
  cond_a = close > MA20(过去 20 日 close 均值)
  cond_b = volume > MEAN20(过去 20 日 volume) * 0.5
两者都满足 → "pass"
仅一个满足 → "fragile"
都不满足 → "fail"
```

### 2.8 `review.ltgd.range`(弹性增强,v7.1 仅用 5 日窗口)

- `LTGD_RANGE_WINDOWS = [5, 10, 20, 50]`(fetcher 落盘四个窗口)
- v7.1 只读 `周期 == "5日"` 那部分
- 字段:`股票代码`、`股票名称`、`累计涨幅`、`排名`
- 用法:对 `longtou_status == confirmed_longtou` 的候选,如果该股不在 5 日 ltgd top 5 → 降级为 `mid_position`

## 3. 共享解析工具(`scripts/duanxianxia_v7_parsing.py`)

所有标签函数必须通过这些工具来 parse 原始 capture 字段,**绝不直接 `int(...)` / `float(...)` 字符串**。

核心接口:
- `parse_money_to_wan(s) -> Optional[float]`
- `parse_int_safely(s) -> Optional[int]`
- `parse_time_to_minutes_after_open(s) -> Optional[int]`
- `parse_pct_string(s) -> Optional[float]`
- `safe_div(num, den, *, default=0.0, den_floor=1e-9) -> float`
- `normalize_dailyline_code(s) -> Optional[str]`
- `parse_status_to_seal_verified(status, status_class=None) -> str`

所有函数:
- 接受 None / "" / "-" / "未" / 非预期类型,不抛异常,返回 None 或 default
- 文件底部带 80+ 个 assert 单元测试,覆盖所有边界
- 入口测试:`python scripts/duanxianxia_v7_parsing.py`

## 9. backfill 规约(`duanxianxia_premarket_v7_1_backfill.py`)

CLI:
```
python scripts/duanxianxia_premarket_v7_1_backfill.py \
    --start 2026-04-13 --end 2026-04-25 \
    --output backtests/v7_1_first_run.jsonl \
    --setup-stats-csv backtests/v7_1_first_run_stats.csv
```

严格规则:
- 对 [start, end] 每个工作日 D:
  - 加载 D-1 capture(home.kaipan.plate.summary、cashflow.stock.{10day,5day,3day,today}、review.fupan.plate、review.ltgd.range、home.ztpool、home.qxlive.top_metrics 09:25 之前最早一份)
  - 加载 D 当天 09:25 时点 capture(4 个 auction.* 表)
  - 运行 v7.1 完整 pipeline,得到当日 top_candidates
  - **严禁查询 D 当天 09:30 之后的任何 capture**(防止 lookahead bias)
- 输出:
  - JSONL:每只候选股一行,带全标签 + 选定 setup + matched_plate_name
  - CSV:每个工作日一行,各 setup 命中数 + top1-5 候选在 D 日实际涨幅(从 dailyline 读 D 日 close vs preclose)

## 10. 上线前 acceptance criteria

- [ ] 1 周历史回放 setup_stats 分布合理(none ≤ 80% 为大致基线,需采样后微调)
- [ ] 至少有 1 个工作日 setup E + B + A 各产出至少 1 只候选(说明分支都活)
- [ ] 没有 setup 因为字段类型/解析问题导致 0 命中
- [ ] backfill 输出的 top1 候选,在 1 周回放里平均 D 日 close 涨幅 > 0(基线门槛,后续优化目标)
- [ ] v7.0 baseline 已知 7 个缺陷(Setup A `none` 缺失、theme_history stub、industry_t1_label 用 len() 计数、Setup B label 写死 hit_strong:acceleration、Setup E 反向指标、Setup E `source_hit_count_min` 表达不了、cashflow 仅 3 分类无 super_ratio)在 v7.1 全部不再出现(单元测试覆盖)
